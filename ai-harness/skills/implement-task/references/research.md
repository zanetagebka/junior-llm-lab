# Research

Keep findings in the task workspace, with links to the files that establish them.

1. Write the questions the task depends on. Drop questions unrelated to its
   acceptance criteria.
2. Answer them from relevant code and documentation. Find the closest existing
   behavior to use as a pattern; do not infer architecture from file names alone.
3. Identify project versions and how to verify the behavior from the README,
   build files, or CI. Consult current official documentation when an API detail
   is uncertain or version-sensitive.
4. Record material unknowns. Ask about a blocking product decision; make and
   document routine assumptions when the task permits judgment.

Check off Research when the evidence is sufficient to plan the scoped change.
