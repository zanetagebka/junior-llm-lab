# Task 19 — Product Experiment

**Module 10 — Product judgment**

## Documentation supplied for the PoC

**Situation:** Earlier lessons should have produced a specific user friction or product weakness. The team wants to test one improvement before committing to a larger Rails change.

**Required behavior:** The brief for this experiment names the user problem, current workflow, non-AI baseline, proposed improvement, success measure, and main risks. The PoC demonstrates only the smallest changed interaction needed to test that hypothesis.

**Acceptance check:** Demo the current and proposed flows with the same fictional question. Explain what feedback or measurement would support continuing, revising, or dropping the idea.

**PoC assignment:** Use Lovable to rapidly test an improved Knowledge Assistant workflow with a product hypothesis grounded in earlier evidence.

**Rails/Strategy:** Write the user problem, current workflow, non-AI baseline, AI hypothesis, metric, risks and smallest experiment. Implement only the smallest Rails change needed to test the hypothesis.

**Compare:** What did the prototype validate about user experience? What did it not validate about model quality, feasibility, security or economics?

**Gate:** Make a next-experiment recommendation from evidence, not attachment to the prototype.
